## (b) Windows 365の休止を避けられるか

| 項目 | 内容 | 区分 |
|---|---|---|
| 休止の主体 | Windows 365はサービス管理として、使っていないCloud PCをAzureの休止（hibernation）で管理する（Service Responsibility） | 【事実】 |
| 復帰 | 対応クライアント（Windows App等）で接続すると自動で再開する。休止前に動いていたアプリは状態を保ったまま再開する | 【事実】 |
| 監視ツール上の表示 | 休止中は「offline」と表示されることがあるが、異常ではない | 【事実】 |
| 時間の設定 | Flex（Dedicated）の「Session State Retention」は既定2時間で設定可能。Business版で休止までの時間を変える設定は、資料で見つからない | 【事実】／【未確認】 |
| Windows側の電源設定 | 休止タイムアウトはグループポリシー／Intune（管理者）で設定する項目。標準ユーザーでは変更できない見込み。またサービス側の休止を止められるかは不明 | 【推測】 |
| 「切断1時間で休止」 | 記録（D004）の値。公式資料ではBusiness版の具体的な時間を確認できない | 【未確認】 |

### R1との関係（事実の組み合わせ・判断なし）
- 休止中はClaude Codeも止まる。Windows Appで接続して起こすと、Remote Controlは自動で再接続する（両方の公式記載より）。
- そのため、休止中に作業させるには、事前にWindows Appで接続して起こす操作が必要になる【推測】。
